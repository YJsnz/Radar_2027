# 装甲圆心策略的离线未来窗口对比

日期：2026-11-10。对应 README 自适应装甲 TODO 的“策略比较”软件子项。

## 1. 范围与数据依据

工具只比较候选圆心的未来覆盖，不创建 ROS 节点、打开串口或生成裁判请求。线上仍只有固定居中与算法选点两种模式；此工具不增加网页选点入口。

评分依据为仓库内《RoboMaster 2027 机甲大师超级对抗赛比赛规则手册 V1.0.0（20261015）》§5.2、印刷页 72–73（PDF 第 73–74 页）：圆内伤害倍率 0.5、圆外 1.5，尚未加固默认态为 1。因此，在冻结的半径下，若未来来袭原始伤害份额 q 落在圆内，条件预计伤害倍率为 `1.5 − q`。它不是已经通过首次激活收益门控的承诺，也不表示实际比赛已经加固。

输入沿用 [内部事件与回放约定](adaptive_armor_implementation.md)：原始 session、逐发有效命中、累计发射/完整性心跳、配置和裁判状态。支持独立 JSONL 与现有 recorder 的 topic 封装，不能由截断的 Dashboard hit_points 补造全量样本。事件校验、坐标、去重及比赛结束处理与已有回放共用。

## 2. 五种候选方法

| 方法标识 | 选点方式 |
|---|---|
| fixed_center | 检测面几何中心。 |
| coordinate_median | 历史命中 X/Y 各自的中位数，作为简单基线。 |
| kmeans | 时间/伤害加权 K-means，确定性初始化、最多 30 轮；在簇中心候选中按训练覆盖选一个。默认 K=3。 |
| maximum_coverage | 复用当前分级网格搜索，最大化实际半径内的历史加权覆盖。 |
| kde_coverage | 在检测面内归一化每个高斯核，再用 32×32 网格近似概率质量，对圆内质量执行相同搜索。默认带宽 5 mm。 |

所有方法共享同一份历史输入、几何、边界策略和半径。中位数与聚类中心会投影到合法整数毫米范围；其余搜索也只输出合法整数毫米坐标。完整内接无解时不缩小半径，候选标记为非法。K、KDE 网格/带宽均为对比工具的工程参数，不能据此认定官方尺寸或最佳实战参数。

KDE 最大化近似圆内概率质量，而不是只取密度最高的单个网格点。网格和最大覆盖搜索都有离散近似误差，不承诺连续空间全局最优。真实离散命中不会因聚类或核密度较低而从原始统计、未来评分中删除。

## 3. 时间切分与评分

1. 第一次具备完整、新鲜输入、已确认几何/边界、有效半径和足够历史样本时，建立选点时刻 cutoff。
2. 训练只使用该时刻已经收到、源时间不晚于 cutoff、位于配置 window_sec 内的来袭点；按源时间保留最多 2000 个预测样本。全局规则统计和未来评分不截断。
3. 保存五种圆心、当时配置及半径。生效半径来自新鲜 0x020E；未生效时沿用有效全局规则估计。此后不使用未来数据回改该次圆心。
4. 未来评分区间为 `(cutoff, cutoff+horizon_sec]`。下一次预测不早于该区间结束，各预测区间不重叠。训练可使用全部已知历史，不再复用线上“较早训练 / 最近验证”切分，因为这里有真正后到的未来评分段。
5. 延迟到达、源时间属于未来区间的有效点仍可作为该窗口结果；延迟的历史点、重复包和 cutoff 时已经知道的超前时钟点不能冒充未来证据。
6. 未来评分不做时间衰减：count 会话逐发等权，baseline_damage 会话按倍率施加前的原始伤害。覆盖 `q = 圆内权重 / 全部权重`；预计倍率为 `1.5 − q`。每个会话汇总按总权重合并，不平均大小不同的窗口覆盖率。

日志或比赛在窗口结束前停止、窗口没有有效来袭、评估期间配置变化时，该窗口不纳入评分，覆盖/倍率为 null。完整性丢失后，本会话已建立窗口也保守剔除，不假定丢失事件只影响最近时间段。未具备预测条件时，skipped_reasons 记录各等待原因的观测次数。

报告按 match_id/source 对应的独立会话保留 recorded_origin（live/replay/synthetic），评估本身始终为 replay，不跨会话、跨来源类型合并成绩。proposal_changes 只是候选坐标变化次数。opportunities_consumed、actual_center_changes、invalid_requests、adaptation_delay_sec 为 null，等待后续机会管理/裁判闭环的反事实模拟与实战对照。

## 4. 运行方式

在仓库根目录运行可复现合成样例：

```bash
PYTHONPATH=radio/src/rm_radio_ros python3 -m rm_radio_ros.core.adaptive_armor_benchmark \
  --input radio/src/rm_radio_ros/test/fixtures/adaptive_armor/synthetic_comparison.jsonl \
  --horizon-sec 10 \
  --output /tmp/armor-benchmark-report.json
```

替换为自己的完整日志时，可加 `--config /absolute/path/adaptive-armor.json`。未指定时，自动读取输入目录的 adaptive_armor_config_snapshot.json；日志中的配置事件随后按原始顺序生效。也支持 JSONL.gz 或 `--input -`，zstd 先通过 `zstd -dc` 解压。参数 `--clusters` 和 `--bandwidth-mm` 分别控制 K-means 的 K 与 KDE 带宽，`--horizon-sec` 默认为 30 秒。

重建 ROS 包后可使用 `rm_adaptive_armor_benchmark` 同名入口。此工具模块本身只依赖现有 Python/NumPy，不依赖 ROS、SciPy 或 scikit-learn。

## 5. 合成样例的实际输出

样例使用人为设定的 100×100 mm 检测面、clip 边界和 5 mm 裁判半径，**不是实体板面标定、官方边界确认或真实比赛记录**。第一局历史与未来热点一致；第二局保持相同历史，但未来热点换到另一角。每局各有一个完整的 10 发未来评分窗口：

| 方法 | 第一局未来覆盖 / 倍率 | 第二局未来覆盖 / 倍率 |
|---|---|---|
| 固定居中 | 0% / 1.5 | 0% / 1.5 |
| 坐标中位数 | 100% / 0.5 | 0% / 1.5 |
| K-means | 100% / 0.5 | 0% / 1.5 |
| 最大覆盖 | 100% / 0.5 | 0% / 1.5 |
| KDE 覆盖 | 100% / 0.5 | 0% / 1.5 |

第二局用于验证未来数据未泄漏给选点：热点突然漂移时，依赖历史的方法同样可能失效。这组构造样例不能证明某种算法在真实比赛更好，也不能用于选定默认带宽、窗口或稳定时间。

## 6. 后续验收

- 用完整真实受击事件和实际发射记录，在固定训练/调参记录之外评估策略；真实数据入口仍待官方/队内接口确认。
- 补充机会授予/消耗、首次收益、稳定观察、实际发送与裁判确认的反事实模拟，评估实际改点次数和适应延迟。
- 用实体检测面和已确认边界验证几何；本工具不解除线上几何、事件源或自动请求门控。
