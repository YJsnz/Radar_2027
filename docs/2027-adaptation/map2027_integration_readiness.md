## 7. 接入问题与具体处理顺序（实施前建议）

### 7.1 正式预设与资产绑定分别做什么

**正式预设**是标定窗口能导入的一组地图点：名称、己方阵营、每层点数和按顺序排列的十二个坐标。导入后，操作者只需在相机画面中选择同编号实体特征，不必重新在缩略地图上点十二次。它仍然不是相机矩阵；当前独立 JSON 尚未写入正式预设库。

**资产绑定**是把一套材料配套管理：2027 地图版本、己方阵营、竖图、横图、同侧 mask、地图点、相机模式／内参档案及对应的新矩阵。加载时核对尺寸、版本与哈希；例如蓝方底图不能误配红方 mask，也不能误用 2026 矩阵。正式预设解决点选复用，资产绑定解决运行文件的一致性。

可以现在先接入地图、同侧 mask、红蓝点位及预设选择，明确标记“尚未实机标定”；矩阵在真实采样后补齐。当前没有实施这些运行入口变更。

### 7.2 相机点和矩阵是否必须等正式上场

不必等正式比赛，但必须能看到真实 2027 场地或已测量、与地图坐标对应的真实特征。

- **现在在室内可做**：用实物棋盘完成当前相机／镜头的内参 K/D，检查去畸变；这不需要完整比赛场地。
- **有练习场或搭建好的场地就可做**：将相机固定在计划安装位，设置最终镜头、对焦、ROI、分辨率，采集红蓝对应点，计算矩阵；也可以对同一安装／图像域下留存的清晰原始帧离线点选和求解。
- **正式安装后需核验**：若训练／拍摄时的相机位置、朝向、镜头、对焦或图像模式与最终安装不同，应按改变内容重新标定并检查。仅移动相机不必自动重做镜头内参，但外参／地图矩阵需要重算；镜头、对焦或成像模式改变时还应重新核验内参。
- 只有 CAD 图或手册俯视图不能提供真实相机对应点；它们可用于仿真或定义世界特征，不能据此声称生成了真实安装可用的矩阵。

如果目前没有能接触的 2027 实体场地，相机到该地图的真实矩阵就仍需等场地可用；其余软件接入、内参与操作准备可以提前完成。

### 7.3 Dashboard 可以先做哪些事

Dashboard 是坐标的显示消费者，更换底图及验证显示不需要等待真实相机矩阵。

1. 从与视觉相同的 2027 资产定义选择 `red_bottom.png`／`blue_bottom.png`，替换旧地图资源、2026 文案和缓存版本；避免视觉、网页各写一套不同版本的路径。
2. 保留统一场地厘米坐标作为输入。当前 `radarCanvasPoint()` 已按红方 `(1500-Y, 2800-X)`、蓝方 `(Y, X)` 转竖图；2027 当前参考画布也是 2800×1500，不需仅因换底图就改变该公式。
3. 以测试点检查四角附近、中心和几个已知特征：缩放、窗口调整、红蓝切换后，同一实体点应仍落到正确位置；测试数据明确标为演示，不调用真实发令入口。
4. 同步地图／标定档案标识与录制清单。已知版本不一致或矩阵缺失时展示清楚的状态，避免将有新底图的界面误认为已完成实机定位。
5. 沿用并核对 `measured`、`occlusion_hold`、`blind_prediction`、`missing` 等状态的显示，使实测、短时保持和盲区猜测能够区分；重新观测、超时和来源切换也要检查。

这部分能先用软件样例完成显示验收，随后再接真实视觉和无线电数据。

### 7.4 盲区预测如何迁移

**先停用旧地图固定预测点，再建立与真实相机视角相关的新盲区。** 停用是后续接入建议，本次没有修改当前 YAML 或启用状态。已有滤波、短时跟踪／遮挡保持作为基线分别验证，不应把所有丢失都当成进入固定盲区。

地图黑绿 mask 只用于两组投影选层，不是相机可见性掩码。真正盲区取决于安装位置、视场和结构遮挡；需要在最终相机画面或同安装录像中，用已知位置的目标检查洞口、墙后、平台背面等区域。

建议按以下顺序实施：

1. **废止旧素材**：2027 运行档案中不继续引用 2026 的 `blind_zone.points`。允许预测的角色单独确认，仅使用有效的 1/3/4/7 集合内角色，不自动把所有角色都打开。
2. **现场标区域**：采集目标可见／消失位置，制作带相机档案和地图版本的遮挡区域多边形；标记入口、出口和对应地形，而不是把整块高地或所有地图外区域当作盲区。
3. **保守预测**：先沿用短时运动跟踪；只有身份可靠、最后位置接近已确认盲区入口、运动方向合理时，才考虑该区域内的少量候选点或路径。预测时长、切换策略与输出条件用回放和实车数据确定，不直接沿用旧赛季参数作为验收依据。
4. **明确退出**：重新识别或收到可信的新鲜位置时停止旧盲猜；超时、身份丢失、候选不在有效区域时转为缺测。融合端同步检查来源新鲜度和允许的预测状态，预测不能伪装成视觉实测。
5. **离线对照再联调**：用同一段目标绕行／进出洞录像，对比“无固定盲猜”与新策略的错误点数、恢复耗时、持续误报和跳变，再决定是否允许预测参与比赛发送。

不能只改 YAML：当前 legacy 的 `blind_zone_roles` 在代码中固定为 1/2/7，`send_point_guess()` 使用 `1-index` 在两个固定点间切换；`correct_only` 和有效目标集合还会影响是否输出。可选 tracking 链路 `_blind_point()` 则从 YAML 读取角色，并按距离／运动方向等给候选打分。后续需检查两套入口及遥测／融合门控；若扩展多候选，legacy 的两点假设也要同步处理。

以上为实施顺序，尚未添加新盲区多边形、预测点或改变当前算法模式。
