# 2027 标定与投影精度代码审阅

日期：2026-11-13。审阅基线：`39910d6`。本次仅做代码、既有文件和离线几何诊断，没有修改比赛算法、掩码、相机配置或标定矩阵，没有实机精度验收。

## 结论与优先级

以定位准确度为优先，建议采用“真实内参 + 统一三维外参 + 已核对的可通行平面/坡面求交”，用独立现场点验证结果。现有黑绿 mask27 可用于区域审阅和旧两层方案的对照实验；它的几何轮廓、标签编码与旋转检查不能证明投影准确。

首先补齐真实相机标定和独立验收，再接入地形投影。当前没有真实 K/D、2027 相机位姿和现场检验点，不能给出已达到多少厘米的结论，也不能根据旧测试文件确定最优坡道分界。

## 当前代码实际执行的流程

| 环节 | 代码 | 当前行为与精度影响 |
|---|---|---|
| 内参/去畸变 | `vision/camera_intrinsics.py`、`intrinsic_runtime.yaml` | 标定与比赛已共用同一套 remap；配置仍关闭，尚无已核验的本机真实 K/D |
| 外参入口 | `vision/calibration.py:931` | 实际求解两张图像到地图的二维单应矩阵；未求相机 R/t，点数据没有真实 Z |
| 拟合 | `calibration.py:933` | 四点用 `getPerspectiveTransform`，多点用 `findHomography(method=0)`；默认六点/层，未做独立验收、误差超限拦截或物理共面检查 |
| 打印误差 | `calibration.py:945` | 在参与拟合的原点上计算地图残差；不是独立点误差，也不是相机图像像素误差 |
| 标定地图 | `calibration.py:479` | 从显示底图点选，缩至 550×900 后点击并取整回原图；地图原生为 1500×2800，单个界面像素约对应 2.73×3.11 个地图像素，尚未计入人眼和低分辨率原图误差 |
| 定位锚点 | `main.py:2609`、`config.yaml:60` | 当前使用车框 `(0.5, 0.92)` 比例点；这是检测框启发式，不保证对应地面接触点或固定物理高度 |
| 选层 | `main.py:444`、`:2621` | 先用地面矩阵投影，按此结果读 mask，黑色保留地面结果，非黑使用第二张矩阵；高层结果未再核对其有效区域 |
| 边界 | 同上 | 读 mask 前就截断到地图边缘、取整数；可能把场外/无效投影压到有效边界。应先判有限性与有效范围，显示阶段再截断 |
| 坐标输出 | `main.py:465` | 两侧竖图转统一横向/裁判坐标；当前名义地图 1 px 对应 1 cm，后续仍需现场核验原点和尺度 |

主识别路径和临时保持路径各有一份选层实现。后续实现新投影时应由一个函数统一消费，避免两条路径产生不同坐标。

代码没有编码固定的“0 cm/300 cm”两个高度。`M_ground`、`M_height_r` 仅是矩阵名称，注释和历史 TODO 不能充当实际平面高度。2027 CAD 的基础地面有两个约 1.5° 的相反坡向；中央高地、公路、梯形高地和制高点也不能由一张共同的“高层矩阵”精确表示。

单应矩阵适用于同一物理平面的图像与地图映射；倾斜坡面也能使用自己的单应矩阵，但不能把多个坡向、不同高度一起当作一个平面。见 [OpenCV 4.8 单应性说明](https://docs.opencv.org/4.8.0/d9/dab/tutorial_homography.html)。增加点数或使用 RANSAC 不能消除非共面的模型误差；RANSAC 还可能将有系统差异的区域当成外点排除。

## 既有数据的离线诊断

读取 `vision/arrays_test_red_points.npz`、`arrays_test_blue_points.npz`，核对其中矩阵与同名 `.npy` 一致，每层均为六点。两个点文件均缺少 `camera_mode`、帧尺寸与 `intrinsics_id`，不能作为新相机的有效标定档案；现有 MindVision 启动检查也会拒绝这类缺少来源的文件。

下面是存储矩阵的拟合残差，以及每次去掉一个点、用其余五点重算单应矩阵、预测被去掉点的留一诊断。数值单位为地图像素，在既有名义画布上数值约等于厘米：

| 旧文件/层 | 拟合均值 | 拟合最大 | 留一均值 | 留一最大 |
|---|---:|---:|---:|---:|
| red 第一层 | 10.02 | 16.36 | 37.06 | 57.66 |
| red 第二层 | 21.41 | 43.60 | 119.97 | 188.45 |
| blue 第一层 | 13.79 | 24.35 | 54.51 | 85.14 |
| blue 第二层 | 24.54 | 53.56 | 99.76 | 160.52 |

这些只是旧点集的稳定性诊断，不是 2027 现场测量精度；留一误差也不是独立采集的验收误差。它提示需要检查点位覆盖、标注、共面性和拟合模型，不能仅看保存时输出的较小残差。

可在仓库根目录复算：

```python
import cv2
import numpy as np

for side in ("red", "blue"):
    with np.load(f"vision/arrays_test_{side}_points.npz") as data:
        for layer in (0, 1):
            src, dst = data["image_points"][layer], data["map_points"][layer]
            h = data["matrices"][layer]
            fit = cv2.perspectiveTransform(src.reshape(-1, 1, 2), h).reshape(-1, 2)
            errors, loo = np.linalg.norm(fit - dst, axis=1), []
            for j in range(len(src)):
                keep = np.arange(len(src)) != j
                h, _ = cv2.findHomography(src[keep], dst[keep], method=0)
                point = cv2.perspectiveTransform(src[j:j+1].reshape(1, 1, 2), h).reshape(2)
                loo.append(np.linalg.norm(point - dst[j]))
            print(side, layer, errors.mean(), errors.max(), np.mean(loo), np.max(loo))
```

还实际检查了以下两项：

- **选层的合成反例**：无畸变针孔相机，合成相机中心 `(0,-10,4)` m，目标 `(5,15,0.3)` m，高区范围 `X∈[4,6]、Y∈[14,16]` m。由准确相机模型生成两张准确矩阵后，地面候选为 `(5.405405,17.027027)` m，正确高层候选为 `(5,15)` m。旧逻辑在地面候选处读到黑色，仍选择地面，产生约 2.067 m 偏差。这是人为构造的机制验证，不是实际安装参数或现场误差；说明矩阵完全准确时，旧选层仍可能失败。
- **去畸变关闭的校验缺口**：用临时 NPZ 保存有效相机模式、尺寸和非空的已去畸变档案 ID，然后以 `intrinsics_id=None` 调用 `validate_camera_calibration`，当前检查会通过。原因是 ID 比较仅在当前 ID 非空时执行；关闭去畸变后可能沿用原去畸变矩阵。应双向核对图像域，且绑定矩阵、地图、相机与内参版本。本次仅确认问题，未改运行代码。

## 推荐实施顺序

### 1. 先建立可信的标定与验收数据

- 用当前固定镜头、对焦、ROI 和分辨率完成真实 K/D，核验去畸变直线与实体几何；标定和比赛保持同一像素坐标域。修正启用/关闭去畸变的双向档案校验。
- 地图点采用 CAD 数值坐标和可重复识别的实体角点，保存明确的 XYZ、单位、坐标系与部件/面版本；地胶图用于显示。不能靠在放大的 981×559 手册图片上点击来建立精密世界坐标，也不能默认图纸等于现场实物。
- 点选支持局部放大和浮点坐标。点应覆盖实际可视范围的远近、左右和多个已核对的高度；预留未参与求解的实体检查点，不能把全部点既当训练又当验收。
- 分开记录相机图像重投影误差（px）和独立点世界平面误差（cm），按距离、地形和红蓝侧报告中位数、P95、最大值，并画误差方向。验收阈值需结合实测目标制定，不能宣称当前已有达标结果。

### 2. 统一三维外参，再按真实地形投影

用真实 K/D 与多个可靠 XYZ↔图像点，求相机 R/t，并进行鲁棒初始化、内点审阅和重投影优化。OpenCV 的 [solvePnP](https://docs.opencv.org/4.8.0/d5/d1f/calib3d_solvePnP.html) 提供这类三维到二维的位姿求解；求解方式和点数应根据实际点集选择，不保证换一个算法就达到现场精度。

对两侧基础斜面、高地、公路、坡道分别保存真实的平面方程及有效多边形；由同一套 K/R/t 派生各平面的单应矩阵，或对像素射线与地形求交。这样坡道使用自己的倾斜平面，台阶按其实际表面或明确的分段近似处理。无需在两个不共面的结果之间按地图颜色做粗略切换，也不建议简单对两个二维坐标按比例插值。

地形必须是已核对的可通行表面集合；现有 `top_surface.npz` 含屋顶、框架和其他最上层结构，不能直接当作机器人地面。坡道与平面的几何边界也应在统一位姿下投到实际相机图像中核对。

每个候选交点需检查：在相机前方、落在对应有效区域、满足该视角的可见性。隧道等上下重叠区域要保留多个层面，结合可见入口和轨迹状态判断；仍不确定时输出低置信度或沿用短时轨迹预测，不能仅凭“最近射线交点”或“最高 CAD 表面”断言目标所在层。后续状态接口变更需同步录制、回放和 Dashboard。

若暂时无法完成三维外参，可先做已确认同一物理平面的分区单应作为过渡，并做候选区域自洽与边界检查；仍要逐区域验收。当前两张矩阵只作为对照基线。

### 3. 单独验证检测锚点和比赛闭环

几何标定通过后，使用实车停在独立已知点上，比较人工选取的真实接触点与检测框 `(0.5,0.92)` 的误差。区分“静态场地点标定准确”和“检测出来的车位置准确”。遮挡、俯视角、检测框变化或取装甲板时，像素锚点可能不在对应地面上；单独调整全局比例不能保证消除物理高度偏差。

先在同一批现场图像/回放中并行比较旧两层结果与新结果，检查坡口跨界跳变、进出洞判层、远近端误差和无效点处理，再切换默认配置。平滑滤波用于抑制噪声，不代替几何精度核验。
