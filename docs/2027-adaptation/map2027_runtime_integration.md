# 2027 地图、标定预设与运行档案接入

日期：2026-11-13。当前软件入口已启用 2027 资产；真实相机对应点、新矩阵和现场误差验收尚未完成。继续沿用现有两层单应投影，不调整用户确认的点位布局，不修改无线电参数或模型。

## 1. 配套资产与启用入口

共享运行素材包为 `radio/apps/match_rx/web/assets/map2027/`，视觉标定、比赛程序与 Dashboard 共用其中的 `profile.json`。档案 ID：`rmuc2027-v1.0.0-display1-two-layer5`，参考场地坐标单位为 cm、范围 2800×1500；竖图 1500×2800。

| 文件 | 用途 |
|---|---|
| `profile.json` | 赛季、尺寸、坐标系、红蓝素材文件名及 SHA-256。 |
| `red_bottom.png`、`blue_bottom.png`、`topdown.png` | 已制作的带地胶显示图，保持原图字节和方向。 |
| `map_mask27_red.png`、`map_mask27.png` | 红、蓝两侧第五版黑绿两层 mask。 |
| `points_R.json`、`points_B.json` | 已确认候选点及原始特征定义／几何依据。 |

该包是已归档显示图、掩码和点集的部署副本，加载时逐文件校验，防止只替换部分资产。原制作目录和说明仍保留；以后更新须同步包、清单、预设绑定并重新标定。ROS 安装规则已包含完整网页及素材包。

`vision/map_runtime.yaml` 默认 `enabled: true`，引用该共享档案。`map_assets.py` 在内存覆盖地图相关项，**不改写用户 `vision/config.yaml` 中的设备、串口、录像及其他本地配置**。因此原 YAML 仍可看到 2026 路径，实际三个入口 `launcher.py`、`calibration.py`、`main.py` 使用覆盖后的 2027 路径。

独立预设库为 `vision/calibration_presets_2027.json`，格式沿用 v2 并增加 `map_binding`；红蓝各有一个“2027 V1.0.0 …候选六点/层”方案。旧 `calibration_presets.json` 及旧矩阵保持原样。自定义保存的预设保留当前资产绑定，实际采样地图点另存于标定 NPZ。

将 `map_runtime.yaml` 的 `enabled` 设为 `false` 仅恢复视觉旧配置入口；Dashboard 本次已固定接入 2027，不会随该开关退回旧地图。2026 遥测不具备匹配档案时会被网页隐藏，不能把这个开关当作整套系统的赛季切换器。

## 2. 正式标定怎么用

1. 按既有方式启动 `vision/scripts/start_launcher.sh`，在“标定与测试”查看地图档案。选择己方阵营后，自动选择同侧六点／层预设；当前显示“待采集相机对应点／新矩阵”。
2. 固定真实相机安装、镜头、对焦、ROI 和分辨率；完成真实内参及图像域核验。运行地图标定，窗口加载同侧带地胶底图、mask 和地图点。自动导入地图点仍保留实时画面；按原操作冻结画面后采样。
3. 按每层 1～6 的顺序采集对应相机特征。参考 [蓝方点位说明](map2027_calibration_points.md)、[红方点位说明](map2027_red_calibration_points.md) 及其总图、局部图；两层各六组对应，不能只采六个相机点覆盖两层。
4. 保存后输出 `vision/calibration-2027/red.npy`／`blue.npy` 及同名 `_points.npz`。保存两层矩阵、实际相机／地图点、相机模式、帧尺寸、内参 ID，以及地图绑定和矩阵 SHA-256。此目录已忽略，不把本机结果当通用实机场地标定提交。
5. 用未参与拟合的已知点和实车位置检验左右、近远、高地、坡口误差，记录安装与图像模式、误差和版本。能保存矩阵并不等于精度验收。

启动台和比赛主程序在打开设备之前拒绝缺失、旧赛季、跨阵营、资产哈希变化或矩阵／NPZ 不配套的结果。取到首帧后继续校验相机模式、实际分辨率与内参 ID；开启或关闭去畸变都要求图像域一致。换相机图像模式、地图或掩码后需重新检查并标定。

当前没有生成任何真实 2027 矩阵。现阶段直接点击比赛启动被阻止是预期行为；标定入口可继续使用。有效对应点可以在练习场、搭建后的场地或同安装条件的真实清晰录像上采集，不必等正式比赛。

## 3. Dashboard 与录制

网页按己方阵营选择共享包内竖图，沿用场地厘米坐标：红方 `(u,v)=(1500-Y,2800-X)`，蓝方 `(u,v)=(Y,X)`。画布保持 1500×2800，窗口缩放使用原有等比显示逻辑。

视觉遥测原 schema `shark.radar.telemetry.v1` 保持兼容，只增加 `vision.map_binding`。字段包括档案 ID／SHA-256、阵营、参考坐标系，以及竖图、横图、mask 和候选点的 SHA-256。融合层保留元数据和既有坐标；Dashboard 对阵营、坐标系及相关素材校验值逐项比对。未携带或不匹配时隐藏视觉图层和来源为视觉的最终点，并显示提示；无线电有效来源仍可显示。这是显示保护，不新增裁判或 RF 参数。

视觉录像 `recording_manifest.json` 增加 `map_binding`、`calibration_sha256` 和 `map_asset_snapshot`。会话目录内 `map_assets/` 复制当时的共享包、实际矩阵和 NPZ，复制后再次校验；以后重新标定不会覆盖录像的几何依据。

无线电比赛记录原始 telemetry JSON，清单另存 `vision_map_binding` 和本次见到的 `map_bindings_seen`。同一会话换过阵营／档案时保留各版本记录，便于审阅。旧日志没有这些字段时仍可读取，但不能认定它使用了新地图；完整离线回放自动选择归档素材、真实录像闭环仍待后续验收。

## 4. 盲区与精度边界

启用 2027 档案时，运行配置强制 `blind_zone.enabled=false`、`points={}`、`roles=[]`，两条视觉算法入口都不能读取旧固定预测点；启动台对应选项禁用。用户原 YAML 中的旧参数没有被删除，亦没有新增未经实测的盲区点。已有跟踪与短时遮挡保持沿用当前设置。

下一步需在最终安装视角实测入口、出口和遮挡区域，再确定预测角色、持续时间和退出条件，使用同一段真实录像对照误报与恢复耗时。两层 mask 是投影选层材料，不是相机可见性图。

第二层候选仍含不同物理表面，隧道上下重叠和坡面仍是现有两层模型的精度限制。本次仅接通资产和来源校验，没有声称消除这些误差。真实内参、两侧矩阵、独立误差记录、2027 模型及裁判／RF 实机验收均继续为 TODO。

## 5. 软件验证

- 真实素材与源目录逐项核对；红蓝预设、黑绿掩码、哈希、方向、错侧／旧矩阵拒绝、内参关闭后拒绝旧图像域均有自动检查。
- 录像快照在后续覆盖源矩阵后仍可独立校验；遥测经融合和比赛录制后保持地图绑定。
- Node 执行网页实际地图函数，检查红蓝四角／中心／参考点、阵营和哈希不匹配的视觉隐藏、无线电来源保留及错误档案提示。
- Qt offscreen 实际创建标定窗口和启动台，检查默认六点、红蓝切换、图像点仍为空、自动预设不冻结取流、旧盲猜禁用；本地配置文件未被改写。
- 浏览器实际加载本地网页及合成坐标样例，确认带地胶地图、叠加位置和档案状态，控制台无 warning/error；没有运行相机、SDR、裁判串口或真实发令。
