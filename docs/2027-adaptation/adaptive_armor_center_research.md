# 自适应装甲圆心策略调研：固定居中与算法选点

日期：2026-11-10。范围：核对规则、协议、当前项目和参考项目，提出后续实现方案；本次不实现算法或改动发令行为。

## 1. 建议结论

保留两种**圆心策略**，共用事件统计、合法性校验、机会门控和裁判确认链路：

| 模式 | 圆心生成方式 | 使用条件与回退 |
|---|---|---|
| 固定居中 `fixed_center` | 使用经过确认的检测面几何中心；矩形检测面为 `(W/2, H/2)` mm | 作为默认选项，方便部署、对照和回放。未知物理尺寸时只显示相对中心，不能发令。选择此模式不代表立即消耗机会。 |
| 算法选点 `adaptive_coverage` | 在允许的圆心范围内，寻找预计能覆盖最多来袭伤害的圆心 | 第一版采用时间加权受击样本的固定半径最大覆盖搜索。数据不足时显示居中候选；无有效覆盖评估时等待，已有加固区则保持，不因回退模式自动改点。 |

推荐第一版使用**时间加权最大覆盖圆**。在此基础上，核密度估计（KDE）可用于平滑受击分布、处理位置测量不确定性；K-means、DBSCAN 可作为离线对照或候选点生成器。最终评估统一使用实际加固半径下的覆盖量和预计伤害，不以聚类质量指标决定是否加固。

“固定居中”是本项目的策略名称。官方“默认状态”表示尚未加固、伤害倍率为 1，两者必须在 UI、日志和策略状态中区分。

## 2. 官方依据与已确认约束

规则依据：根目录《RoboMaster 2027 机甲大师超级对抗赛比赛规则手册 V1.0.0（20261015）》§5.2，印刷页 72–73（PDF 第 73–74 页）。已提取完整相关页，并渲染核对公式和表 5-5。

协议依据：根目录《RoboMaster 2027 机甲大师高校系列赛通信协议 V1.0.0（20261029）》：命令总表、表 1-16（0x0206）、表 1-24（0x020E）、表 1-34（0x0121）、表 1-43（0x0A03）、表 1-45（0x0A05）。以下结论以仓库内上述版本为准；公开规则中心可用于后续跟踪修订，本次不能据其动态页面确认不存在新版或后续答疑。

- 每经过 1 min 获得一次可累积机会；**己方当局累计打中对方的弹丸数达到 10** 后才具备请求条件。己方装甲被击中的数量用于防护决策，不应直接作为这个命中门槛。
- 一次指令选择或改变一个圆心，作用于己方所有机器人、前哨站和基地装甲模块。不能为每台机器人分别下发不同圆心。
- 装甲模块采用统一坐标系：检测面左下角为原点，X 向右、Y 向上，单位 mm。不能将各模块未经确认地归一化到 0～1 后混合成毫米坐标。
- 加固区伤害倍率为 0.5，区外未加固部分为 1.5，尚未加固的默认状态为 1；它们与其他攻击/防御增益乘算。
- 面积由相对准确率决定：`η = 击中对方的所有弹丸数 / 己方发射的所有弹丸数`；先取所有命中点 X、Y 各自的中位数 `(x0,y0)`，再取到该点距离的中位数得到 `σ`；`Λ=η/σ`、`ρ=Λ己/Λ对`、`A=S板×ρ²/(2+ρ²)`。
- 下行 0x0121 的 8 字节偏移是加固计数，单调每次 +1；9/11 字节偏移是 uint16 毫米圆心。**指令不包含半径**，算法不能通过下发另一个半径改变裁判面积。
- 0x020E 提供己方剩余机会、是否生效、当前圆心与半径；裁判实际生效范围以该回报为准。0x0A05 尾部只提供对方公开加固圆。

官方面积统计与选点预测需要分开维护。规则使用当局“所有”命中和发射，不能用仅保留最近几十发的统计冒充规则公式；近期窗口、时间衰减可以用于推测对手接下来的打点。`σ=0`、无发射分母、丢包严重或统计起点不全时，标记估计不可用，不擅自添加 epsilon 并声称结果为官方面积。

### 2.1 现有材料尚未解决的规则问题

1. **检测面尺寸与面积基准**：统一坐标系不等于所有模块外形、尺寸相同。需要确认自定义装甲、其他模块、前哨和基地之间的物理坐标与面积约定；不能套用旧装甲板尺寸或插画尺寸。
2. **圆与边界关系**：所核对页没有明确要求“完整圆必须包含在检测面内”。当前页面候选圆使用这一保守约束，但它不能被描述为已经核实的官方要求。若圆允许跨边缘，实际覆盖应按 `圆 ∩ 检测面` 计算；若完整圆必须内接，圆心范围才是 `[R,W−R]×[R,H−R]`。两种约束的最优解会不同。
3. **边界约束可能无解**：对于假设的正方形检测面，完整内接圆最多占面积的 `π/4≈78.5%`，规则公式的面积占比则可趋近于 100%。这说明必须确认边缘处理，不能为了通过 UI 校验缩小裁判给定半径。
4. **面积更新时机**：需要确认 A 是随统计持续更新还是在请求时确定，以及半径取整方式；不能仅凭条文推定刷新周期。激活前没有 0x020E 生效半径时，只能使用有完整依据的规则估计并标明来源。
5. **取消加固**：所核对的 0x0121 表没有给出主动取消加固、恢复默认状态的字段。已经加固后不能假定在不利情况下可以随时撤销；首次加固尤其需要收益判断。

## 4. 应该优化的目标与首次激活条件

来袭受击点为 `p_i`，已知半径为 R，候选圆心为 c。令 `w_i` 表示时间权重，若能可靠区分原始伤害，再乘以该弹丸在应用装甲区域倍率前的预计伤害；没有可信伤害信息时统一按一发一票。

```text
覆盖估计 q(c,R) = Σ w_i · 1[||p_i−c||≤R] / Σ w_i
建议圆心 c* = argmax q(c,R)，c 属于已经确认的允许圆心范围
```

这里 q 表示“来袭伤害中落在圆内的份额”，**不是命中率 η**。双方 η、σ 影响可加固半径；己方装甲被击中的空间分布决定圆应放在哪里。单独一个命中率数值不含空间位置，无法据此选出合理圆心。

在来袭分布、其他增益和原始伤害可比的假设下，相对于首次加固前的默认状态，预计装甲伤害倍率为：

```text
M(c) = 0.5×q(c) + 1.5×(1−q(c)) = 1.5−q(c)
```

因此，**第一次加固只有在 q>0.5 时预计降低伤害**。例如覆盖 70% 时，倍率为 0.8，预计减少 20%；覆盖 30% 时，倍率为 1.2，预计增加 20%。这些是依据规则倍率的推导，不是实机效果或预测保证。

两种模式应共用激活判断：首次激活以经过独立评估的覆盖下界超过 `0.5+安全余量` 为候选条件，再检查比赛阶段、机会、己方累计有效攻击命中 ≥10、统计完整性与几何合法性。样本不足、面积未知或链路无效时，保持候选预览/等待状态。固定居中模式也不应伪装成“无数据即可安全加固”。

已有加固区时，需要在**同一个当前/预测半径、同一份评估样本**上比较新旧中心的 q。更换中心不需要重新套用“相对默认”的 50% 门槛；应要求预计改善足够大且稳定，值得消耗一次不可即时补充的机会。保留当前中心、中心候选和统计中位点，都应参与比较。不要假定能取消已有加固。

## 5. 算法比较与第一版方案

| 方法 | 优点 | 与本任务的关系及限制 |
|---|---|---|
| 固定几何中心 | 无选点参数，结果稳定 | 作为默认策略与评估基线；对偏向一侧的受击分布可能覆盖不足。 |
| 坐标中位数/几何中位数 | 简单、对个别极端点更稳健 | 可作为候选点与基线；规则中的坐标中位数用于计算 σ，不自动成为最优加固圆心。 |
| K-means 聚类 | 能分离部分多峰分布，便于解释打点群 | 需指定 K，目标是簇内平方距离，不是半径 R 内的伤害覆盖；取某个簇的中心仍需统一评分。 |
| DBSCAN/HDBSCAN | 能识别不规则命中群，DBSCAN 无需指定群数 | 群可能很长，群中心不保证覆盖最多样本；参数敏感，真实稀疏命中不可直接当无效数据丢弃。 |
| KDE 热力分布 + 圆形区域积分 | 可平滑位置噪声，适合展示与多峰分布 | 应最大化圆内概率质量，不能只取热力图最高的单点；需要选择带宽并处理板面边界。 |
| 固定半径最大加权覆盖圆 | 直接对应预计受击防护目标；半径变化后可重新评分 | 样本经验最优不等于未来最优；须加时间权重、独立评估、稳定性和机会管理。推荐第一版主方法。 |
| GMM/强化学习 | 可表达多攻击模式或多步决策 | 当前缺少真实样本和可靠环境模型，尚不能证明优于直接覆盖优化；暂不作为第一版依赖。 |

一个用于解释目标差异的理想化例子：假设 70 发击中 `(30,60)`、30 发击中 `(80,60)`，半径 12 mm。全样本均值是 `(45,60)`，两团都覆盖不到；放在 `(30,60)` 能覆盖 70%。这是人工构造的数学反例，不是比赛采样，也不代表多簇 K-means 在所有数据上都失败。

### 5.1 建议实现路径

1. 按比赛维护全量统计；另维护用于选点的近期受击队列。使用固定的比赛时间基准作指数衰减 `w_time=exp(−Δt/τ)`，保留全局分布作为稀疏窗口的先验。τ、窗口长度、最少有效样本数均为后续回放调参项，不写成官方参数。
2. 从确认的模块几何与官方/估计半径构建允许圆心集合。先在网格上计算覆盖分数，再对多个高分候选细化；将几何中心、当前生效中心和统计候选一并纳入。
3. 第一版可直接遍历样本计算覆盖；数据增多后可评估“二维加权直方图与圆形核卷积”。如引入 KDE，使用检测面内归一化和边界处理，避免把板外概率当作可防护样本。半径 R 与平滑带宽 h 分开配置，不能为平滑而改变实际半径。
4. 以输出协议可表示的整数毫米坐标重新评分、重新检查几何。粗网格或局部搜索只声称“搜索到的最佳候选”，不能声称连续空间全局最优；小样本可用经过验证的精确最大覆盖实现作离线对照。单纯网格细化不保证覆盖率误差上界。
5. 多模块共用同一毫米圆心，但保留模块身份、检测面和伤害权重。不同尺寸时按各模块 `检测面 ∩ 圆` 的预计覆盖联合评分；未知坐标映射时标记不可合并，不做缩放猜测。
6. 来袭伤害权重使用原始伤害及其他增益，不能直接用已经乘上 0.5/1.5 后的扣血量作权重，否则会产生策略反馈偏差。若额外提高基地等目标权重，必须单列为战术价值权重并与“全队伤害最小”目标区分。

### 5.2 置信度、防抖与机会消耗

- 10 发是请求资格，不是统计充分性的证明。记录有效样本数、来自多少独立射击片段、分布更新时间、链路缺失情况和覆盖估计区间。
- 同一连射中的命中相关，不能直接将所有弹丸当独立样本套简单二项置信区间。采用时间分块留出/回放评估，或按射击片段做分块 bootstrap；后者也需要验证分块和分布假设。
- 搜索与验证使用同一批数据会产生乐观偏差。覆盖下界须基于未参与该次选点的时间块；离线使用滚动前向验证，在线可先固定候选收集后续命中再确认。数据不够时只给建议，不标成高置信度自动请求。
- 改点要求预计收益超过阈值、中心稳定持续一定时间、无待确认请求；近似同分时优先保持当前中心，再以固定规则打破平局，保证回放可复现。
- 微小漂移不发新请求；切换 UI 模式只改变策略配置。机会按 0x020E 实报累计，不按本地计时虚构。首次激活与后续改点分别记录收益和消耗原因。
- 请求后等待 0x020E 状态回报，综合检查圆心、生效状态、机会变化与状态新鲜度。超时进入待核对状态，不能盲目再次递增加固计数；串口写成功不能视为生效，回报本身也没有独立 request_id。

## 6. 后续可独立验收的工作顺序

1. **明确数据和规则边界**：取得真实命中事件接口，确认攻击/受击方向、事件去重和实际发射统计；核实检测面尺寸、跨边缘及面积刷新规则。
2. **固定居中模式**：增加赛前模式配置、毫米居中候选和预览说明；保留当前手动候选工具。无有效数据和发令条件时展示具体等待原因。固定模式与算法模式共用门控，不能通过默认选项绕过条件。
3. **离线统计与选点**：实现独立事件统计器、纯逻辑覆盖搜索及确定性回放；数据不全时验证“不估算、不发令”的行为。合成数据只作算法验证，不能标成真实比赛状态。
4. **比较预测表现**：居中、坐标中位数、K-means/DBSCAN 候选、加权覆盖、KDE 覆盖统一按未来时间块的伤害评价，选择参数。
5. **ROS/UI/发令闭环**：同步检查发布者、订阅者、Dashboard、录制和回放；共用 `/rm_radar_algorithm/radar_cmd` 语义入口与底层计数管理，完成裁判回读和超时验证后才勾选大功能。

回放至少包含：中心单峰、偏心单峰、两峰、环形/长条、均匀散布、瞄点切换、大小伤害混合、多模块尺寸、序号回绕/乱序/重复、数据断流、σ=0、未知半径、半径改变及大圆跨边缘。指标记录后续样本覆盖率、相对默认/现中心的伤害变化、无效请求数、机会消耗次数、适应延迟、运行耗时和置信区间可靠性。算法优劣须在真实或明确标注的回放上比较；本次没有运行这些算法实验或裁判联调。

## 7. 在线调研来源

以下均为论文作者所在机构或库的官方资料；应用到本项目的策略建议和风险阈值是本文推导，不是资料对 RoboMaster 效果的背书。

- [Chazelle 与 Lee，On a circle placement problem，1986](https://collaborate.princeton.edu/en/publications/on-a-circle-placement-problem-2/)：固定半径圆覆盖最大点权重的形式化问题；与本项目经验覆盖目标一致。论文摘要所述算法和复杂度不代表本项目已经实现或验证了对应精确算法。
- [scikit-learn：K-means](https://scikit-learn.org/stable/modules/clustering.html#k-means)：需指定簇数，优化簇内平方距离；这与本项目的圆内覆盖目标不同。
- [scikit-learn：DBSCAN](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.DBSCAN.html)：邻域 eps 不限制整个簇的直径，不能把它直接设为加固半径后就认为簇内都能被一个圆覆盖。
- [scikit-learn：Kernel Density Estimation](https://scikit-learn.org/stable/modules/density.html#kernel-density-estimation)：带宽控制平滑偏差/方差；本项目应积分圆内密度，并核实边界处理。
