# MV-SUA133GC-T 内参运行时接入

## 目标与范围

内参求解仍由 `tool/start_intrinsic_calibration.sh` 负责。本改动将其导出的 K/D 安全接入地图外参标定与比赛推理：两个入口在 MindVision SDK 原始 BGR 帧进入 `camera_image` 前调用同一个 `RuntimeCameraIntrinsics.bind()` 和 `BoundCameraIntrinsics.apply()`，使用同一尺寸、同一 K、同一五参数畸变模型，不裁剪也不缩放。车辆/装甲检测、像素点选取、外参拟合、显示与录像均消费相同的去畸变像素坐标。

配置默认关闭，因此不改变现有比赛画面、旧地图矩阵或 `vision/config.yaml`。此项不生成真实 K/D，也不替代新场地外参点位核验。

## 配置步骤

1. 在 `tool/intrinsic_calibration.yaml` 填写实测棋盘格参数、相机序列号、镜头和对焦记录；采集真实图像并完成解算。人工审阅整体/逐张误差、覆盖、多角度样本、直线去畸变效果和实体几何。
2. 核实 SDK 产品名为 `MV-SUA133GC-T`，报告包含非空序列号、完整 ROI/缩放/binning 档案、实测宽高、镜头和对焦记录。普通导入图片不会通过运行时的实机来源检查。
3. 打开 `vision/intrinsic_runtime.yaml`，把 `solution.directory` 指向导出的 `solution-...` 目录。路径可以相对该配置文件，也可以是绝对路径；填写与报告完全一致的 `camera.model`、`serial`、`lens`、`focus` 和可接受的 `max_rms_px`。
4. 仅在实际相机与报告逐项核对、实体棋盘和独立几何检查完成后，将 `physical_validation_confirmed` 与 `enabled` 设为 `true`。
5. 先运行外参标定，重新采集并保存红/蓝地图矩阵。然后启动比赛主程序。比赛会校验外参点文件记录的内参档案 ID；换 K/D、ROI、分辨率、相机、镜头或对焦记录后，都需要重新做地图外参标定。

## 启动核验

配置启用时，采集线程按 YAML 中序列号打开唯一相机，并比较实时 SDK 产品型号、序列号、完整 ROI/缩放/binning 字段、BGR 彩色输出以及帧宽高。任何字段不一致都会拒绝当前图像；比赛入口停止，外参标定不能保存结果。停用配置时保留既有相机和图像流程。

内参档案 ID 是相机身份/模式、尺寸、K/D 与畸变模型的 SHA-256。地图 `_points.npz` 保存该 ID，比赛入口启用内参时必须与当前 ID 一致。比赛录像清单也记录该 ID（未启用时为 `null`）。

`lens` 与 `focus` 是实物记录，SDK 无法读取镜头和对焦环位置；运行配置须与标定报告一致，现场还须人工确认镜头和焦点没有变化。ROI 与尺寸则由 SDK 和实拍帧自动核验。

## 当前验收边界

- 软件接入已实现；默认运行 YAML 未启用，未修改用户现有 `vision/config.yaml`。
- 当前没有本机真实棋盘采集样本或已核验的 K/D，因此不能启用去畸变，也不能声称像素映射/外参结果已通过现场验收。
- 后续需用本机实拍结果完成配置绑定、相机身份/ROI/尺寸拒绝与通过检查、直线和已知地图点核验，并确认红蓝外参重新标定结果。
