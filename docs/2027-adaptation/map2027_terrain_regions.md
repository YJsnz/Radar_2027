# 2027 CAD 地形候选分区与掩码

制作日期：2026-11-13。依据 RMUC2027 V1.0.0 STEP 转换后的真实三角网格，生成投影方案审阅用的区域、坡面和结构候选掩码。它们还不是已验收的相机遮挡区、比赛禁区或可行驶区域。

来源、坐标范围和地胶显示图见 [地图资产处理记录](map2027_asset_processing.md)。产物位于 `vision/images-2027/terrain-v1.0.0/`，源文件与 CAD/显示资产版本绑定在 `manifest.json` 中。

## 提取方法

1. 核对 CAD 清单、部件记录、深度参考和地胶图的校验值，并检查缓存声明的 STEP 版本。
2. 根据 GLB 装配路径、真实顶点和三角形索引、世界变换，把 VTK 的 286 个绘制对象分别绑定到 81 个 CAD 叶子实例。VTK 返回对象的顺序与 STEP 装配顺序不同，因此不能用枚举顺序直接分配部件编号。
3. 以与已有底图完全相同的正交相机绘制部件 ID 和三角面坡度。关闭抗锯齿、光照和透明度影响，用互补的颜色通道检查标签是否被插值或改变。
4. 按部件名称和装配路径分类。使用真实可见轮廓，不将部件包围盒填充成区域。两侧基础地面在中轴线处分开，保留其相反的坡向。
5. 从变换后的三角面法向计算坡度，单位为度，栅格量化步长为 0.5°。再与已有 CAD 高度图的有限差分坡度独立核对。

渲染保留的是从正上方看到的最上层几何表面。即使某处画出了平台或屋顶，也不能据此判断机器人能否通过；顶层表面同样不能还原隧道内部的多层通路。三角面标签渲染忽略材质透明度，因此也不等于相机的光学遮挡结果。

## 区域编号

| ID | 名称 | 含义 |
|---:|---|---|
| 0 | unknown | 未命中 CAD 几何的像素 |
| 1 | ground_y_low | 参考坐标 Y 小于 750 cm 的可见基础地面 |
| 2 | ground_y_high | 参考坐标 Y 大于 750 cm 的可见基础地面 |
| 3 | central_highland | 中央高地地面部件 |
| 4 | trapezoid_highland | 红蓝梯形高地部件 |
| 5 | commanding_structure | 制高点上下侧部件，含坡面或边缘 |
| 6 | road_structure | 公路部件组，含坡面和结构件 |
| 7 | resource_structure | 资源区部件组，不能自动细分为可走平台和工作台 |
| 8 | fortress_structure | 堡垒部件 |
| 9 | tunnel_boundary | 中央高地侧边隧道挡边部件，不代表隧道通路 |
| 10 | fan_frame | 名称明确的风机框部件，不保证包含全部风机本体 |
| 11 | other_structure | 未分入上述类别的 CAD 结构，需要审阅 |

类别是项目的几何整理约定，不是裁判协议字段或官方规则区域。名称来自 CAD，不能将其直接解释为比赛规则中的允许/禁止状态。`component_roles.json` 保存部件路径、允许的区域编号及图元数。

## 资产和编码

三组 PNG 均提供 `topdown`（2800×1500）、`red_bottom` 和 `blue_bottom`（1500×2800）三个方向，坐标公式沿用 CAD/地胶资产清单：

- `regions_*.png`：单通道、无损 8 位 PNG，像素值直接为上表编号，不是预览配色。
- `ramp_candidates_*.png`：0/255 二值图。在 3～8 类几何中选择坡度大于 4°且小于 35°的表面，供审阅坡面。两个阈值均为项目筛选启发式，不是官方坡度或通行门槛。
- `structure_review_*.png`：0/255 二值图，标出 9～11 类结构、坡度至少 35°的表面，以及未知像素。这是审阅提示，不是已经确认的禁用区域。
- `terrain.npz`：包含 `region_ids`、从 1 开始对应 CAD 部件的 `component_ids`、单位为度的 `slope_deg`、两个布尔候选掩码和坐标矩阵。未知坡度为 NaN；0 部件编号表示无效。
- `regions_preview.png`：地胶底图上叠加区域颜色和图例。
- `surface_review.png`：地胶底图上用橙色显示坡面候选、红色显示结构/陡面/未知审阅区。
- `manifest.json`：来源校验值、各文件校验值、区域统计、坡度量化、基础地面平面公式和独立校验指标。

地面平面公式以 CAD 毫米坐标表示为 `Z_mm = a*X_mm + b*Y_mm + c`。它来源于图纸中基础地面的 1.5° 坡度，不代表所有高地都能使用同一张单应矩阵。

## 与当前投影程序的关系

当前 `vision/main.py` 的两条投影路径仍根据掩码是否为纯黑来选择两个单应矩阵。本次新产物是多类别标签，需要先改造投影消费者并重新采集对应平面的标定点，才能接入。不能直接把 `regions_*.png` 填入旧的 `paths.map_images.mask`。

本次没有修改比赛默认配置、旧赛季矩阵或已有掩码，也没有自动生成盲区预测点、相机视角遮挡区或规则禁区。相机安装位置和真实场地核验尚未完成，上述项目继续保留 TODO。

## 复现

使用 `tool/requirements-map2027.txt` 中的 CAD 渲染依赖。已经存在本地 CAD 缓存和已提交的底图时，从仓库根目录运行：

```bash
python3 tool/build_2027_terrain.py
```

缓存默认位于 `tool/data/map2027/`，不提交大体积 GLB。缓存缺失时先按 [地图资产处理记录](map2027_asset_processing.md) 从原始 STEP 重新运行 `export_2027_map.py mesh`。已有 CAD 和显示资产与缓存版本不一致时，程序拒绝输出。

脚本支持 `--cache`、`--cad`、`--display` 和 `--output`。本次实际使用 VTK 9.1.0，在可访问的 X 显示中离屏渲染。

## 实际验证记录

- 成功绑定 81 个部件、286 个图元；12 个区域编号均有输出，区域像素数之和为 4,200,000。
- 有效几何与坡度覆盖率约 99.999714%，12 个像素保留未知；与原 CAD 深度图的覆盖一致率为 100%。
- 在同一部件的内部像素中，对 3,708,318 个地形样本比较三角面法向坡度与独立高度梯度：差值中位数约 0.000059°，95 分位约 0.133491°。该检查验证坐标轴、法向变换和栅格提取一致性，不表示现场几何精度。
- 中央高地包围矩形中有 310,590 个像素没有被误标为中央高地；轮廓来自实际几何而不是矩形填充。
- 坡面候选为 315,967 个像素，约 31.6 m² 的标称地图栅格面积，不作为可通行面积或比赛合法区域的结论。
- 三方向 PNG 的旋转关系逐像素一致；区域编号、0/255 二值编码、基础地面两侧划分、NPZ 结构、文件校验值和图像完整性检查通过。
- 错误 STEP 版本缓存会在渲染和创建输出目录之前被拒绝；已实际做负例检查。
- 两张预览图已目视检查，脚本 Python 编译和 `git diff --check` 通过。未运行相机、真实裁判链路或现场投影测试；未运行无关通讯/视觉模型全量测试。
