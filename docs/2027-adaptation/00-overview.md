## 0. 结论先行

1. **算法与架构基本可复用，2027 的活儿主要在三处**：兵种换血（英雄/工程/空中 → 重装/3/4/哨兵）、协议字段拉伸（0x020E 1→8B、0x0121 8→13B、0x0A04 8→12B、0x0A05 41→47B、0x0003 20→24B）、新增「自适应装甲加固」决策（**决策权在雷达**）。
2. **协议帧接入仍不完整**：截至 2026-11-10，radio的0x0003/0x020E/0x0A04/0x0A05已按24/8/12/47B解析，0x020C位图也已更新。实际差异包括0x0A01～03保留槽仍被当成机器人、两条0x0305组帧保留位写入坐标、视觉0x0121仍8B，以及0x0A05重装键未同步到易伤策略。详细证据和接收范围见 [当前协议对照报告](protocol2027_compliance_audit.md)；不能把不属于雷达当前链路的全部命令变化都列作阻塞。
3. **0x0305 仍 48B，但槽位语义变了**：每方 6 槽 = 重装(0-3)/保留(4-7)/3 号(8-11)/4 号(12-15)/保留(16-19)/哨兵(20-23)，己方从 24 起同构。现码按 `1,2,3,4,6,7` 填，**帧合法但 2/6 号数据写进了保留位**，选手端看不到、也拿不到工程/空中的替代信息。
4. **当前所附2027手册未给出完整RF参数验收依据**：规则明确写干扰波具体参数后续发布，通信协议给出了新载荷。现有2026频点、带宽、调制与接入码应标为待确认配置，不能仅凭载荷解析成功就宣称2027空口兼容。
5. **干扰波密钥压制是新胜负手**：破译对方 6 位密钥上报成功 → 对方干扰波难度 +1；而「对方难度 > 己方时，己方雷达准确标记也不产生易伤、不积累双倍进度」。这条把「密钥破解速度」变成了易伤系统的前置条件，`auto_password_node` + 0x020E 等级跟踪要升级为一等公民。
6. **视觉侧改动集中在"编号集合 + 标定资产"**，不在网络结构：重装替代英雄/工程、空中退出地面识别，`armor.yaml`/`blind_zone_roles`/`allowed_numbers`/地图掩码/双层仿射全部要按 2027 场地重做。

## 1. 系统全貌（现状）

```
              ┌──────────── vision/ (Ubuntu 22.04, 海康 4024x3036) ────────────┐
              │ hik_camera → YOLOv5(car 640 / armor 1280) → 颜色+编号 → 双层仿射 │
              │ (0cm / 300cm) → 2800x1500 战场系 → Kalman/跟踪 → 盲区预测        │
              └───────────────┬──────────────────────────────────────────────┘
                              │ ROS2 话题 /rm_radar_algorithm/telemetry
                              │ JSON schema=shark.radar.telemetry.v1, 20Hz, 单位 cm
              ┌───────────────▼──────────── radio/ (ROS2 Humble + GNU Radio) ──┐
   ANT1 ──────┤ flowgraph_node(gfsk/RX.py)      → 0x0A01~0x0A06 解析            │
   ANT2 ──────┤ flowgraph_node(ganraoyuan/RM.py, 干扰波) → 0x0A06 密钥         │
              │        ↓ String(JSON) 话题                                     │
              │ radar_integration_node：视觉/无线电双源融合（0.5s/1.0s/2.0s）    │
              │        ├─ 0x0305（48B，'<24H'，≤5Hz）→ 服务器 → 己方选手端       │
              │        ├─ double_vulnerability：双倍易伤决策 → 0x0121             │
              │        └─ invincible_targets：私有 0x0301/0x0234 → 己方机器人     │
              │ referee_serial_node：唯一串口写者（/dev/shark-referee 115200）    │
              │ auto_password_node：按 0x020E 允许时刷新密钥                      │
              │ match_recorder / match_dashboard / rx_autotune                   │
              └────────────────────────────────────────────────────────────────┘
```

关键约束（读码确认）：

- **单串口写者**：视觉不直接开串口（`config.yaml` 的 `referee.transport: radio_ros`），所有裁判帧由 radio 侧 `referee_serial_node` 统一写，视觉只发遥测；`legacy_serial` 分支仍保留（`vision/RM_serial_py/ser_api.py`），是旧路径。
- **进程间只传 String(JSON)**，没有自定义 msg —— 加字段不用改接口，但**没有编译期保护**，字段名拼错就是静默 0。
- **配置通道单向三跳**：ROS 参数 → `RM_RADIO_*` 环境变量 → 流图 `__init__` 读 env（`nodes/flowgraph_node.py:445-494`、`flowgraphs/gfsk/RX.py:70-156`）。加 2027 参数必须同时改这三处，漏一处就在场上表现为「参数不生效」。
- **空口层是隐藏耦合点**：8B Access Code + 4B 长度域(`00 0F 00 0F`) + **固定 15B Payload**，长帧（0x0A01 33B、0x0A05 50B）靠 `RefereeFrameAssembler` 跨包拼接（`core/rm_protocol.py:48,289,364-473`）。15B 是硬约束，2027 换包长会连带 `flowgraph_node.py:1079-1094`、`offline_iq_scan.py:22`、`jiang.py:42-43`。
- **采样率 2MS/s 在 `flowgraphs/gfsk/RX.py:251` 构造期硬编码**，`RM_RADIO_SAMPLE_RATE` 构造时被忽略，只能事后用 setters 设。
- **0x0305 三重限速**：协议 5Hz、`referee_serial_node:918` 速率上限、`run_algorithm.py` 调度器（实际跑 4.8Hz）。2027 上限仍是 5Hz，可保留。
- **双源融合策略**（`core/radar_integration.py:216-311`）：对方机器人且无线电新鲜(1.0s) → 用无线电；否则视觉 measured/occlusion_hold/blind_prediction；否则 missing；幽灵位 2.0s 清空。**这条策略 2027 依然成立**，因为信息波内容没变。

## 2. 2027 规则变化（雷达视角）

### 2.1 兵种与系统

| 项目 | 2026 | 2027 |
|---|---|---|
| 1 号 | 英雄 | **重装机器人**（英雄+工程合并） |
| 2 号 | 工程 | **保留**（不上场，协议留位） |
| 3/4/5 号 | 步兵 | 步兵（不变） |
| 6 号 | 空中机器人 | **空中系统**（含机库，**不进雷达无线链路**） |
| 7 号 | 哨兵 | 哨兵（不变） |
| 9 号 | 雷达 | 雷达（不变） |

- 雷达系统：可配自定义终端 **0 台**、无操作手、自动运行（最多 1 个遥控器用于调试）。
- 雷达功能只剩两项：**雷达识别 + 解析信息波**。2026 的"雷达反制/激光照射空中机器人"整章删除 → 2026 的激光链路必须下线。
- 多机通信：可向所有己方机器人发送，**只能接收哨兵**的数据（与 2026 相同）。

### 2.2 标记机制 P（与 2026 逐字相同，可直接复用）

- P ∈ [0,150]；准确 d<0.8m → x=+1.0（上次准确/半准确）否则 x=1.0；半准确 0.8≤d<1.6m → ±0.5；错误 d≥1.6m → -0.8；**累计 0.5s 无数据 = 一次错误**；P=P+x 截断到 [0,150]。
- 阈值：对方 [0,100) 无增益；[100,120) **15% 易伤**；[120,150] **20% 易伤**；己方 [50,150] 只显示真实位置、无增益。
- 双倍易伤：累计使对方易伤 1 分钟得 1 次机会（多台不累加计时），触发后所有雷达来源易伤 ×2 持续 30s，**每局至多 2 次**。
- 复活后 P 保留、x 归 0。定位模块离线 → 对方雷达对该机始终"准确"、己方雷达始终"错误"（2027 新增条款，`rules2027.txt:1543-1546`）。
- 5Hz 连续准确：0→100 约 2.8s，第 3.0s 达 120（手册示例）。

### 2.3 雷达要新增的决策：自适应装甲加固（2027 新增，决策权在雷达）

- 双方每 60s 各得 1 次可累积机会；**当局累计命中弹丸 ≥10 后，雷达可随时发指令**消耗 1 次，选择一个圆心。
- 效果：该方**所有机器人 + 前哨站 + 基地**装甲模块上，以该圆心、面积 A 的圆形区域为"已加固"，其余"未加固"。伤害倍率：未加固 ×1.5 / 已加固 ×0.5 / 默认 ×1（与攻防增益**乘算**）。
- A = 装甲板面积 × ρ²/(2+ρ²)，ρ = Λ己/Λ对，Λ = η/σ；η=命中率，σ=命中点散布中位半径；**装甲模块坐标系：检测面左下角为原点，右 x、上 y**。
- 每发命中的 (x, y, 区域类别) 通过常规链路发给受击方，**同时通过雷达无线链路发给攻击方**。
- 雷达侧数据入口：0x020E（剩余机会、当前生效圆心/半径）；出口：0x0121 byte8-12。

### 2.4 干扰波与密钥压制（2027 表述更硬）

- 干扰波三级难度，**具体参数后续发布**（2027 手册不再给频点/调制参数）。
- 信息波内容 8 项：各机器人位置 / 血量 / 剩余发弹量 / 当前增益 / 队伍剩余经济 / 队伍总经济 / 增益点激活状态 / **装甲受击信息**（新增）。
- 干扰波含对方 6 位（数字字母）密钥，开局与难度变化时重置。
- 雷达解析密钥并上报成功 → 对方干扰波难度 +1；**当对方难度高于己方，对方雷达即使准确标记也不产生易伤、不积累双倍进度**。

### 2.5 场地与雷达基座

- 战场 28m×15m（2800×1500 单位成立），围挡 2.4m，PVC 地胶；公差 <100mm ±5mm、≥100mm ±5%、角度 ±3°。
- 雷达基座平台 3.4m×1.16m，中央与战场中心轴线对齐，**距地约 2.4m（2026 为 2.5m）**，四周 1.1m 围栏；配 1920×1080 HDMI 显示设备 + HDMI 线 + 新国标 5 孔 220V 插座。
- 结构大改：新增制高点（三级台阶）/机库平台/工作台/风机/科技核心/隧道（金属板）；取消飞行区/停机坪/飞坡/无线充电区。梯形高地 200mm/23°、中央高地 12°（高度未给数值）、公路 11/15°、能量机关靶 308/300mm、下坠 0~50mm。
- 影响：**外参必重标**；"0cm 层"不再能当纯平面（高地/台阶需要分段或高度补偿）；"300cm 层"按 2.4m 重算；遮挡可视域重做。

### 2.6 赛制、流程与合规

- 3min 准备（上一场结束且雷达撤出后即可提前上基座；剩 30s 全上电；剩 15s 搬离；结束后遥控器交指定区）→ 15s 自检 → 5s 倒计时 → 7min → 结束。
- **结束判定双触发**：时间耗尽 ∨ 提前获胜（基地被击毁）→ 录制/统计收尾不能只依赖 420s 超时。
- 胜负顺序：基地击毁 → 累计控制度 → 全队攻击伤害 → 全队剩余总血量 → 平局加赛（2026 比前哨站剩余血量）。
- 雷达不获金币、无等级/经验；初始 800 金币、每分钟 +100、00:59 +300（兑换项已无"空中支援"）。
- 合规红线：R15 **仅雷达**可用赛场官方电源供自备设备；R3 禁自架无线设备/对讲机；R59 禁带无线调试器；R23 雷达遥控器须交出否则红牌；R53 敌机器人不得攻击雷达；表 7-5 禁干扰裁判系统检测。

## 5. 未知与风险（必须持续跟官方确认）

1. **2027 射频物理层参数未发布**：频点、带宽、SPS、BT、Access Code、帧长、发射功率全未知；2026 的多级干扰频点表（`rules2026.txt:2875+`）不能想当然沿用。
2. **中央高地/制高点/台阶高度**部分未给数值 → 视觉分层方案存在不确定性。
3. **加固圆心如何映射到各模块坐标系**（机器人/前哨/基地各自模块尺寸不同）手册未细化；0x0A05 的 41-46 给的是"对方自定义装甲模块检测面"坐标系，不能直接当世界坐标用。
4. 0x020E byte1 的"剩余加固机会数"与 0x0121 的单调计数需与服务器实际行为对拍（建议实验室用礼盒/裁判系统模拟器先验）。
5. 规则遗留措辞：协议附录仍出现"红方停机坪"（2027 已取消停机坪）；手册附录 2 标注"待更新"。
6. 雷达是否允许主动发射（除官方发射源外）在 2027 手册未明确 —— 我们现有链路只收不发，属安全边界，别越界。

## 6. 建议实施路线

1. **阶段 0 · 建立对照基线（1~2 天）**：把 2026/2027 字段差异写成机器可读常量表（单一真源 `core/radio_config.py` 或新 `protocol2027.py`），并给每条命令加长度断言日志；用 2026 录制回放 + `lab_tx` 空口闭环验证"不改逻辑只改字段"不破坏现有功能。
2. **阶段 1 · 协议层打通（P0）**：按上表 1-8 改长度表/解析/构造 → 用离线 IQ 回放 + 虚拟裁判帧单测跑通；重点验证 0x0A04/0x0A05 不再丢帧、0x0305 槽位正确、0x0121 13B 合法（递增校验）。
3. **阶段 2 · 新决策（加固 + 密钥压制）**：独立 `armor_fortify.py` 决策器（纯逻辑 + 单测，先离线用 2026 数据回放），再接到 `radar_integration_node`；同时把 0x020E 加密等级纳入"是否值得标记"的策略门控。
4. **阶段 3 · 视觉/场地重标（并行）**：编号集合与模型类改 1/3/4/5/7；地图/掩码/双层仿射/盲区点按 2027 场地重做；投影层改高度分段。
5. **阶段 4 · 射频参数落地（等官方）**：`AirLayerProfile` 抽象 + 参数化采样率/包长，官方参数一发布只改配置，不动算法。

验收口径建议：每条协议命令一条"长度 + 语义"断言测试；0x0305 实发率 ≥4.8Hz 且槽位自检；加固决策可离线回放复现；视觉 2027 场地重投影误差 <0.1m。
