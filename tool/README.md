# 开发工具

## 迈德威视内参标定

运行 `./tool/start_intrinsic_calibration.sh`。所有采集/棋盘参数在 [intrinsic_calibration.yaml](intrinsic_calibration.yaml) 填写，棋盘格行列数和实测方格边长默认留空；标定报告导出后，比赛与地图标定的统一去畸变配置见 [内参运行时接入说明](../docs/2027-adaptation/intrinsic_runtime_integration.md)，工具输出与边界见 [内参标定说明](INTRINSIC_CALIBRATION.md)。

## Qt 装甲命中模拟器

在 Qt 页面构造命中信息，经现有 ROS 事件话题发送给雷达融合节点，由雷达站计算统计、建议圆心与半径。Qt 和比赛接收台只展示回传结果。

### 启动

先更新并重启雷达站主程序/融合节点，让本次新增的模拟会话结束接口生效。需要现有 `rm_radar_integration` 节点正在运行，装甲会话空闲；网页显示还需要 Dashboard。模拟工具本身不启动相机、SDR 或裁判串口。

在仓库根目录执行：

```bash
./tool/start_armor_simulator.sh
```

与雷达站使用非默认 ROS 域时，例如双方均使用 199：

```bash
./tool/start_armor_simulator.sh --domain-id 199
```

脚本加载 `/opt/ros/humble`，使用系统 Python 3 和仓库源码；依赖项目已有的 PyQt5、rclpy、NumPy。它会为 PyQt5 设置自己的插件目录，不导入 OpenCV。工具不会更改 ROS 域以外的系统设置或安装依赖。

“开始模拟”仅在收到新鲜状态、发现唯一融合状态发布者且雷达站未绑定其他装甲会话时可用。若未就绪，检查主程序是否已启动、两端 ROS_DOMAIN_ID 是否一致，以及旧模拟是否已经结束；不需要用模拟裁判包欺骗比赛阶段。

### 操作

1. 设置己方、固定居中/算法选点、模拟检测面的毫米宽高。默认 100×100 mm 仅为示例，不是官方尺寸或实体标定。
2. 点击“开始模拟”。工具发送唯一会话，收到雷达站接纳回报后，再应用临时预览配置；自动请求关闭、实体几何未确认、规则边界未确认，不保存配置文件。
3. 选择命中方向：**来袭命中**指对方击中己方，用于圆心选点；**己方攻击命中**用于累计己方命中数与规则统计。填写 X/Y，或点击装甲图选择待发送的命中位置；再点“发送单发命中”。橙色十字是待发送命中位置，不能手选算法圆心。
4. “单发对应发射数”默认为 5，即该方向模拟实际发射 5 发，其中本次有 1 发命中。未命中的其余发射仍计入分母，不是裁判允许发弹量。工具每 0.5 秒发布最新累计发射统计/心跳；热点示例固定使用每次命中对应 5 发的分母。
5. 点击“发送热点示例（含历史样本）”，发送己方攻击 40 发、来袭 100 发，分别累计模拟发射 200/500 发；热点以当前 X/Y 为中心，散布由输入框指定。示例明确包含历史训练与近期验证样本，因此无需等满 30 秒即可看到算法圆。每次事件序号唯一，不将同点重复命中误当重复包。
6. 查看 Qt 的红色来袭点、蓝色虚线建议圆、远端已接收计数和等待原因；也可打开雷达站的 `/#armor`。网页模拟期间展示 Qt 临时配置，并禁用网页配置保存；结束后恢复正常操作。
7. 点击“结束模拟并恢复配置”，或正常关闭窗口。工具先等待自己的模拟会话被清空，再恢复开始前的运行配置；支持重复开始新会话。配置文件全程不改写。

单发/少量同点命中可能因样本不足或散布为零无法估计半径，这是现有算法的正常等待状态。工具不通过伪造半径或替换算法结果强行画圆。历史样本会随时间退出预测窗口，长时间演示时可再发示例或继续发送命中。

### 通信与边界

| 通道 | 方向 | 内容 |
|---|---|---|
| `/rm_radar_algorithm/armor_events` | Qt → 雷达站 | 原有 v1 内部 session/hit/shots，新增 end_session。 |
| `/rm_radar_algorithm/adaptive_armor_config` | Qt → 雷达站 | 原有 v1 配置；只用于临时预览及恢复。 |
| `/rm_radar_algorithm/adaptive_armor` | 雷达站 → Qt / Dashboard | 统计、点、建议圆、门控原因、错误；Qt 不独立计算圆。 |

来源固定为 `qt-armor-simulator`，会话 origin 固定 synthetic，坐标为左下角原点、向右 X、向上 Y 的非负整数毫米。所有点按每发等权计算；示例伤害不代表混合弹种的真实伤害。

新增 end_session 必须匹配当前比赛 ID、来源、schema、坐标系和时间，并且当前会话只能为 synthetic/replay、没有未核对请求。它不能清空 live 会话。录制保留原始事件和配置；离线回放将 origin 标成 replay，也能重放模拟结束事件。

工具不发布 `/rm_radar_algorithm/radar_cmd` 或裁判状态，不构造 0x0121/0x020E 帧；synthetic 输入也不能越过现有发令门控。来源名称用于区分预览流程，不是 ROS 身份认证。

若进程被强制杀死或关闭时雷达站已经不可达，无法确认结束和恢复。此时需核对并重启融合节点以清除遗留模拟会话、重新加载磁盘配置；不要把预览数据作为真实比赛输入。正常结束有确认流程，不依赖向真实裁判状态话题注入假包。

### 验证

2026-11-10 使用隔离 ROS 域、临时配置、真实融合节点、Dashboard 及离屏 Qt 按钮验证了接纳、单发/示例发送、统计/圆回传、固定居中、结束恢复、再次开始和正常关闭；原配置文件保持不变，裁判请求话题收到 0 条请求。包含模型、会话清理与联动的 16 项工具测试通过。

浏览器在隔离域 199、端口 8766 上核对网页显示 100 个来袭点和 1 个算法圆：建议中心约 (18,81) mm、半径 11.1 mm，保留“等待裁判状态”，未显示虚构的裁判生效圆；控制台无错误。上述均为合成演示，不是官方受击接口或实机加固联调验收。
